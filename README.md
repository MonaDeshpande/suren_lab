# S Testing Laboratory Customer Test Request App

Streamlit + PostgreSQL application for **S Testing Laboratory**.

## Features

- **Login & roles** — admin, reception, analyst, reviewer (up to **2 roles** per user; admin is exclusive)
- **Reception** — Customer Test Request form, permanent customer master (GST), filled PDF/Word
- **Manual sample codes** — reception enters date, lab code, and unique sample code per sample
- **Analyst** — protocol worksheets, calculations, protocol PDF/DOCX, status updates
- **Reviewer** — review reception + analyst data, generate **Final Test Report** PDF (QSF 7.8.2)
- **Admin** — register users, assign/change roles, reset temporary passwords; view audit log
- **Audit trail** — every create/update/delete records who, when, and what in `audit_log`
- **Report stamps** — CTR and Protocol show Generated by + date/time; Final Test Report has no generator stamp (reviewer signs with pen)
- **50-day retention** — sample rows expire and are cleaned up; customers stay permanent

## Letterhead and document templates (client site)

Header/footer designs are **Word files** under `reference/`. Edit them in Microsoft Word
(Insert → Header / Footer), save, and restart the app. There is no upload screen in the UI.

| Format | File(s) |
|--------|---------|
| **CTR** | `reference/Customer Test Request form LLP.docx` |
| **Protocol** (same header/footer in each) | `Jaggery Protocol LLP.docx`, `Basic Nutrition Protocol 2026.docx`, `Water protocol 2025.docx`, `Micro Protocol.docx` |
| **Final report — with logo** | `Test Report Format.docx`, `Water test report.docx`, `Micro Test Report.docx` |
| **Final report — without logo** | `Test Report Format (no logo).docx`, `Water test report (no logo).docx`, `Micro Test Report (no logo).docx` |

Reception **Report format** (A / B / Both) selects which final-report template is used.
Without-logo templates must keep the **same body tables** as the with-logo file; only
header/footer should differ.

Optional runtime logo for PDF letterhead: replace [`assets/logo.png`](assets/logo.png)
(~**7.25 × 1.42 in** aspect ratio). Protocol and final-report DOCX headers come from the
Word templates above, not from this file.

Paths are listed in code via `services/document_templates.py` (`client_template_manifest()`).
## Quick start

```bash
# 1. Env file (defaults: 127.0.0.1:5433)
copy .env.example .env

# 2. Start PostgreSQL in Docker
docker compose up -d

# 3. Create all tables/columns (client site: double-click create_table.bat)
pip install -r requirements.txt
python scripts/table_creation.py

# 4. Seed default admin (first install only), then run
python scripts/seed_admin.py
streamlit run app.py
```

The app also runs idempotent migrations on startup/login (`db/migrate.py`), so an
older Docker volume is brought up to date automatically (e.g. `user_roles`).

Or double-click `run_app.bat` (after `seed_admin.py` once).

Open http://localhost:8510 and sign in.

### Default admin

| Username | Password   |
|----------|------------|
| `admin`  | `Admin@123` |

Admin registers other users with a temporary password. Those users **must change password on first login** before using the app.

### Roles

Each staff account may have **1 or 2 roles** (e.g. reception + analyst). The **admin** role cannot be combined with other roles.

| Role | Access |
|------|--------|
| **admin** | All pages + user management |
| **reception** | Reception (CTR + sample codes + customer master) |
| **analyst** | Analyst (protocol + calculations) |
| **reviewer** | Reviewer (review both + final PDF); may also open Reception to edit customer master |

**Credentials** (Docker DB): host `127.0.0.1`, port `5433`, user `sls_user`, password `sls_secure_password`, db `sls_lab`.

## Multi-user login and operation

Multiple staff can use the app **at the same time** on different machines or browsers. Each browser gets its own login session; all users share one PostgreSQL database.

### Recommended lab setup

1. **One host PC** runs Docker Postgres + Streamlit (`run_app.bat` or `docker compose up -d` then `streamlit run app.py`).
2. **Other PCs** open a browser to `http://<host-ip>:8510` (the host IP is printed when `run_app.bat` starts).
3. Each person signs in with their own username. There is no limit on simultaneous logins.

`.streamlit/config.toml` binds Streamlit to `0.0.0.0` so other machines on the LAN can connect. Only the host needs database access; client PCs use the browser only.

### How sessions work

- Login state lives in **Streamlit session state** per browser — not in a global server variable or database session table.
- **Logout** clears only that browser's session.
- **Admin deactivates a user** or changes roles → that user's next page load re-checks the database and shows the login form if the account is inactive.
- **Same user, two browsers** — allowed (no duplicate-login block).

### Role-based data access

| Role | Workspace | Sample visibility |
|------|-----------|-------------------|
| reception | CTR + customer master | All samples |
| analyst | Protocol + calculations | Only samples assigned to them |
| reviewer | Review + final PDF | All samples |
| admin | User management + all workspaces | All samples |

Users may hold **1–2 roles** (e.g. reception + analyst). Concurrent edits to the same record are last-writer-wins; the **audit log** records who made each change.

### Not implemented

Server-side session registry, blocking duplicate logins for one account, real-time edit warnings, and optimistic locking are not part of the current design.

## Sample workflow

```
Admin creates user accounts (1–2 roles: reception / analyst / reviewer)
    → staff change temp password at desk
Reception saves CTR
    → one DB row per sample + sample_code + tests_to_perform
    → expires_at = now + 50 days
Analyst opens sample_code
    → protocol + calculations → status completed
Reviewer opens sample
    → reviews reception + analyst data
    → Generate Final Report PDF → status reported
Cleanup (auto on app open, or manual):
    python scripts/cleanup_expired_samples.py
```

## Permanent vs sample data

| Permanent (`customers`) | 50-day samples (`request_samples`) |
|-------------------------|--------------------------------------|
| Name, address, contact, email, GST | sample_code, tests, status, remarks |
| Kept forever | Deleted after `expires_at` |

CTR headers (`test_requests`) are kept for audit; only expired **sample** rows are removed.

Users (`users`) are permanent login accounts.

## E2E demo document bundle

`run_e2e_demo.bat` (or `python scripts/generate_e2e_downloads.py`) generates sample
CTR, protocol, and final report files under `downloads/e2e_demo/`.

**Default (app flow):** requires PostgreSQL (`docker compose up -d`). The script runs
the same service layer as the app:

1. **Reception** — `save_test_request()` (customer + sample in DB)
2. **Analyst** — `upsert_protocol_header()` + `save_test_result()` per test
3. **Reviewer** — `generate_final_report()` with ULR and marks sample `reported`

**Offline fallback** (no database): `python scripts/generate_e2e_downloads.py --offline`

Demo E2E pytest (not run by `run_tests.bat`): `pytest -m e2e tests/integration/test_e2e_app_flow.py`

Routine test run: `run_tests.bat` runs the full suite **except** `-m e2e` demo flows.

**Dummy CTR + protocol previews (unique GST, auto DB cleanup):** requires PostgreSQL.
Included in `run_tests.bat` when Postgres is up. Writes files under
`tests/output_preview/integration/` for visual review:

```bash
pytest tests/integration/test_dummy_document_generation.py -v -s
```

## Analyst protocol (shared 11-test library)

Reception selects catalog tests (Moisture, ash, sugars, …). Those formulas are
**shared** — any sample name that selects Moisture gets the same worksheet.

Analyst page: protocol header → Appearance → per-test inputs/formula → page-1
results → Generate protocol PDF/DOCX. Status: pending → in_progress → completed.

**Reviewer** generates the customer Test Report PDF (QSF 7.8.2) and sets status to
`reported`.

Empty required fields show a **popup**. Run once if upgrading an existing DB:

```bat
docker exec -i sls_lab_db psql -U sls_user -d sls_lab < scripts/migrate_protocol.sql
python scripts/seed_admin.py
```
